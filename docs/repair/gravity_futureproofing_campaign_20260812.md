# Gravity future-proofing campaign — 2026-08-12

This record is an implementation closure note, not a scientific certification.
The current repository was authoritative; the 2026-08-11 future-proofing audit
was used as the finding map.

## Implemented architecture

- adaptive tree-node reserve seeded from leaf occupancy and prior high-water;
  no unconditional `2*N` node reservation;
- optional quadrupole node lanes and compositional tree/runtime/PM/exchange
  memory accounting, plus checked pre-run gravity memory budget estimation;
- source-indexed production targets instead of duplicate x/y/z target lanes;
- fixed-width radix ordering for Morton keys and periodic seam preprocessing;
- strong `GravitySourceGeneration`, `TreeBuildGeneration`, `PmFieldVersion`,
  `ForceEvaluationEpoch`, and `DecompositionEpoch` identities;
- explicit `GravitySourceSnapshot` for authoritative/predicted force-epoch state;
- PM capability tiers that distinguish diagnostic naive DFT from production
  FFTW, with no silent production fallback;
- topology-neutral PM decomposition descriptor and explicit GPU backend
  architecture ownership; current transposed slab and host-FFT CUDA staging are
  labelled accurately rather than promoted to unimplemented backends;
- shared inlinable tree interaction/MAC/softening-envelope logic;
- compact top-level source-domain ownership map plus locality-driven target
  export, MPI distributed-graph neighborhood communication, and overlap of
  local traversal with nonblocking request transport;
- LET/domain cache validity bound to source/decomposition/tree-build identity;
- source-bound acceptance-manifest tooling and stale-readiness invalidation;
- focused authoritative gas ownership/direct-softened-force/refinement tests and
  a nonzero-softening Ewald sweep launcher.

## Deliberately bounded

- hierarchical timesteps and PM cadence greater than one remain production
  disabled pending validated predictor/reuse semantics;
- true 2-D pencil FFT is represented by the ownership interface but not
  fabricated without a vetted backend;
- CUDA remains host-FFT staging until a real persistent device FFT path exists;
- distributed isolated/open PM remains the explicit bounded root-workspace path;
- 32-bit local tree indices remain the default compact policy with checked
  ceiling; global IDs are separate.

## Acceptance rule

A manifest is current only while its gravity-source fingerprint matches the
working tree. MPI/FFTW/HDF5/CUDA evidence must be generated by the corresponding
runtime and attached to the exact source fingerprint; the executable does not
self-certify.

## Structural memory changes

The campaign changes the allocation architecture rather than claiming an
unmeasured production-size RAM reduction:

- production source-index targets no longer retain a second three-double
  coordinate triplet (`24` bytes per target of long-lived coordinate capacity);
- for the default tree leaf size of 16, the first-build node-capacity seed is
  approximately `N/8` plus a root/headroom term instead of `2*N` (about a
  16-fold smaller initial node-capacity seed); vectors remain checked and may
  grow for clustered/degenerate trees;
- monopole builds do not allocate the seven double quadrupole/second-moment
  lanes, avoiding 56 bytes per allocated tree node in that profile;
- Morton ordering uses fixed-width key/index radix workspaces rather than a
  comparison-sort permutation based on `size_t` indices;
- runtime, tree, PM, communication, and persistent force-cache memory are now
  reported compositionally, with unknown external FFT/CUDA allocations kept
  separate instead of guessed into the owned total.

No 256^3/512^3 production memory benchmark was run in this environment, so no
measured peak-RAM or wall-time speedup is claimed here.

## Verification actually executed

Toolchain detection was performed once. GCC/CMake/Ninja/OpenMP and HDF5 were
available. MPI compiler/runtime, FFTW development libraries, CUDA/nvcc, and
compute-sanitizer were unavailable.

- `cpu-only-debug` configured and the complete supported CPU Debug repository
  build linked successfully after the final edits.
- The source-bound serial gravity release gate passed 5/5 tests:
  `unit_tree_gravity`, `unit_pm_solver`,
  `integration_tree_gravity_vs_direct`,
  `integration_tree_pm_coupling_periodic`, and
  `integration_star_formation_source_runtime`.
- Additional focused CPU tests passed:
  `integration_pm_scale_factor_regression`,
  `integration_provenance_roundtrip`, and the tiny
  `integration_dmo_empty_rank_smoke_single_rank` diagnostic-backend smoke.
- The HDF5 Debug profile built the affected snapshot/provenance surfaces and
  passed `unit_snapshot_hdf5_schema`, `integration_snapshot_hdf5_roundtrip`,
  and `integration_provenance_roundtrip`.
- ASan/UBSan builds completed through the repaired gravity libraries. Runtime
  passes were obtained for `unit_tree_gravity`,
  `integration_tree_gravity_vs_direct`, and
  `integration_tree_pm_coupling_periodic`. `unit_pm_solver` was stopped rather
  than claimed after the no-FFTW naive DFT became prohibitively slow under
  sanitizer instrumentation.
- A strict CPU/no-MPI/no-FFTW/no-CUDA warning build of `cosmosim_gravity`
  completed without gravity-subtree warnings after the campaign changes.
- `tools/gravity_acceptance_manifest.py` created and verified a current-source
  evidence manifest. The final CPU Debug source fingerprint used during this
  verification pass was
  `680a1587ad726201f47d44fe7e531eb347e31c7df572b83b59a78b78812d98de`.

No runtime acceptance is claimed for MPI, FFTW/Ewald production profiles, CUDA,
or compute-sanitizer. The broader repository CTest catalogue was not used as a
campaign-wide green claim: bounded full-suite runs also encounter unrelated
legacy fixtures/validation modes and dependency-gated tests outside this gravity
future-proofing acceptance set.

## Required before the first multi-rank DMO production cube

The exact packaged source still requires a production FFTW+MPI acceptance run:
np1/np2/np3/np4 (and the intended poster rank count) periodic TreePM/rank
comparisons, Ewald including the nonzero-softening sweep for the chosen profile,
PM decomposition edge cases/empty ranks, HDF5 Zel'dovich and restart/rank
equivalence, migration/restart paths, strict MPI+FFTW warnings, and a small
intended-rank rehearsal recording peak memory, LET peer/byte telemetry, and
wall-time. These are release/scientific evidence gates, not missing local
implementation claims.
